**p4n4-lib 0.4.1** lets clients create `p4n4-net` on the subnet a project asks for, so a project whose default range overlaps another network (a VPN's, or another Compose project's) can start.

```bash
pip install p4n4-lib==0.4.1    # Python 3.11+
```

## Highlights

- **`layout.network_subnet(project_dir, layers)`:** the subnet for `p4n4-net`, from `P4N4_SUBNET` in the first layer's `.env` that sets it (iot's first, where p4n4-iot reads it), else `layout.NETWORK_SUBNET` (`172.20.0.0/16`). `layout.SUBNET_KEY` names the key. Clients pass it to `compose.ensure_network()` instead of the constant, so the network they create matches the one p4n4-iot declares.
- **A clearer error when the subnet is taken:** `compose.ensure_network()` adds what to do when Docker reports an overlapping pool (set `P4N4_SUBNET` to a free range, e.g. `172.28.0.0/16`), and falls back to the command's stdout when stderr is empty.

## Compatibility

- Required by **p4n4 (CLI) 0.4.1**. p4n4-api 0.3.0 and p4n4-emu don't create the network and keep working with 0.4.0 or 0.4.1.
- No API removed or changed: a drop-in upgrade from 0.4.0.
